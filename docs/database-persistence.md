# Database & Persistence

Agent-MCP's core state (agents, tasks, agent-to-agent messages, project
context, file metadata, OAuth identity bindings, and Claude Code session
tracking) is stored in a relational database. Two backends are supported:

| Backend | When it's used | Notes |
|---|---|---|
| PostgreSQL | `DATABASE_URL` is set | Recommended for any deployment where the server is redeployed/restarted (e.g. DigitalOcean App Platform, whose local disk is ephemeral). Durable across restarts. |
| SQLite (local file) | `DATABASE_URL` is unset | Default for local development. Unchanged from earlier versions: a single file at `<project-dir>/.agent/mcp_state.db`. |

RAG content (`rag_chunks`, `rag_meta`, `rag_embeddings` — the vector search
index) always lives on a local SQLite file regardless of `DATABASE_URL`,
because it's fully regenerated by the RAG indexer from your project's
markdown/code/tasks/context on a timer. There's nothing to lose by not
persisting it durably: after a redeploy it just re-indexes (a few minutes,
uses OpenAI API tokens). When running with `DATABASE_URL` set, this cache
lives at `<project-dir>/.agent/rag_cache.db`; without it, RAG data shares
the same single SQLite file as everything else (unchanged historical
behavior).

## Configuring PostgreSQL

Set these environment variables (e.g. via Doppler, or your platform's
secrets manager — never commit them):

| Variable | Required | Description |
|---|---|---|
| `DATABASE_URL` | Yes, to use PostgreSQL | Standard `postgresql://user:pass@host:port/dbname` connection string. SSL is required (`sslmode=require` is applied automatically). |
| `DB_POOL_MIN_SIZE` | No (default `1`) | Minimum pooled connections. |
| `DB_POOL_MAX_SIZE` | No (default `10`) | Maximum pooled connections. |

On startup, the server automatically applies any pending versioned schema
migrations (`alembic upgrade head`, via `agent_mcp/db/pg_bootstrap.py`) — it
never drops or recreates existing tables. Migrations live in
`agent_mcp/db/migrations_pg/versions/`; add new ones with:

```bash
alembic revision -m "describe the change"
```

Then edit the generated file's `upgrade()`/`downgrade()` functions and
commit it alongside your code change.

## Local development (SQLite)

No configuration needed — just don't set `DATABASE_URL`. This is unchanged
from previous versions and is the recommended setup for local development
and the automated `testing-suite/`.

## Portability notes for contributors

Application code talks to the database through
`agent_mcp/db/connection.py`'s `get_db_connection()` (core tables) and
`get_rag_db_connection()` (RAG tables only), which return a connection
object with the same interface regardless of backend: `.cursor()`,
`.commit()`, `.rollback()`, `.close()`, `row["column"]` access, and SQLite's
`?` placeholder style (translated automatically for PostgreSQL). Existing
`except sqlite3.Error` handlers continue to catch PostgreSQL errors too —
see `agent_mcp/db/portable.py` for details.

`INSERT OR REPLACE` is SQLite-only syntax; for tables that need an upsert
and are shared between both backends, use
`agent_mcp.db.portable.upsert_sql(dialect_of(conn), table, key_columns,
all_columns)` instead of hand-writing the SQL.
